# Время отклика API (локальные операции)

Требование кейса: интерфейс реагирует на простые локальные операции быстрее 1 с.

Замер: `python3 scripts/eval/latency.py` по запущенному стенду, Apple M4, локальный PostgreSQL 15, офлайн-режим,
имитированная задержка корпоративных сервисов выключена (`CORP_LATENCY=0ms`), 25–40 запросов на операцию.
Время — полный HTTP-запрос с клиента, мс.

| Операция | p50, мс | p95, мс | max, мс |
|---|---|---|---|
| GET /api/route — маршрут стажёра | 0.3 | 0.4 | 0.5 |
| GET /api/actions — заявки и квитанции | 0.2 | 0.2 | 0.3 |
| Чат: «Как проходит код-ревью?» (поиск по базе) | 0.3 | 0.6 | 0.7 |
| Чат: «Что мне делать дальше?» (маршрут) | 0.4 | 0.5 | 0.6 |
| Чат: «Оформи отгул на 18 ноября» (план + MCP-календарь) | 0.4 | 0.6 | 0.8 |

В демо-стенде задержка сервисов намеренно включена (`CORP_LATENCY=350ms`), чтобы было видно статус ожидания.
LLM-режим не замерялся (нет ключа): ответ модели добавляет секунды, поэтому чат не блокирует интерфейс —
индикатор «Тропа думает…», кнопка «Отменить», таймаут 45 с и офлайн-ответ при сбое.
