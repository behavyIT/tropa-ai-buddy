# web-ui Specification

## Purpose
Веб-интерфейс: три колонки для стажёра (маршрут · чат · «сейчас»), вкладки для наставника/руководителя/HR BP.

## Requirements

### Requirement: Вход и рабочие места по ролям
UI SHALL показывать вход тестовыми персонами и рабочее место по роли.

#### Scenario: [UI-01] Вход персоной
- **WHEN** пользователь выбирает «Алекс Новиков»
- **THEN** вход с тестовым паролем и три колонки: маршрут, чат, следующий шаг

#### Scenario: [UI-02] Вкладки руководителя
- **WHEN** входит руководитель
- **THEN** вкладки «Согласования», «Команда», «Вопросы», «Тропинки», «Флаги», «Чат»

### Requirement: Неблокирующий чат
Обращения к агенту SHALL NOT блокировать интерфейс: статус ожидания, отмена, понятная ошибка и повтор.

#### Scenario: [UI-03] Ошибка и повтор
- **WHEN** сервис отвечает 503
- **THEN** показана ошибка с кнопкой «Повторить», повтор успешен

#### Scenario: [UI-04] Отмена
- **WHEN** пользователь нажимает «Отменить» во время ожидания
- **THEN** запрос прерван, ошибка не показывается

#### Scenario: [UI-05] Карточки и источники
- **WHEN** ответ содержит источники и карточки
- **THEN** отображаются цитаты с пометкой «Тестовая инструкция»/«Ответ наставника», карточки действий, шагов, человека, teach-back, заявок и 👍/👎

#### Scenario: [UI-06] Безопасный рендеринг
- **WHEN** текст содержит HTML
- **THEN** он выводится как текст, маркеры [n] — как сноски

### Requirement: Карточки действий
UI SHALL показывать план (поля, предупреждения, права), подтверждение, квитанцию и правку дат.

#### Scenario: [UI-07] Подтверждение и квитанция
- **WHEN** пользователь нажимает «Отправить заявку»
- **THEN** появляется квитанция с ID и статусом «На согласовании»

#### Scenario: [UI-08] Правка дат
- **WHEN** пользователь меняет даты до отправки
- **THEN** отправляется PATCH с новыми датами

### Requirement: Явный API-клиент
Клиент SHALL проверять ответы Zod-схемами, ставить CSRF-заголовок, различать сеть/таймаут/отмену.

#### Scenario: [UI-09] Сеть, таймаут, отмена
- **WHEN** fetch падает, истекает таймаут или запрос отменён
- **THEN** коды `network` / `timeout` / `aborted`

#### Scenario: [UI-10] CSRF-заголовок
- **WHEN** выполняется POST
- **THEN** JSON-тело и `X-Requested-With: tropa`

### Requirement: Демо-пульт и маршрут
#### Scenario: [UI-11] Машина времени и уведомления
- **WHEN** нажата «+1 день», пункты демо-меню, колокольчик
- **THEN** вызываются API демо, уведомления открываются и помечаются прочитанными

#### Scenario: [UI-12] Действия в маршруте
- **WHEN** пользователь нажимает «Начать», «Готово», «Напомнить», «Сдать в чате», «Запросить», «Материал»
- **THEN** вызываются API маршрута или вопрос уходит в чат

### Requirement: Смена пользователя
#### Scenario: [UI-13] Выход возвращает на экран входа
- **WHEN** пользователь нажимает «Сменить»
- **THEN** сессия завершается, данные прежнего пользователя удаляются из кэша, показывается экран входа
