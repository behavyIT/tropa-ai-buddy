# corporate-mcp Specification

## Purpose
Подключение корпоративных сервисов через MCP (JSON-RPC 2.0, Streamable HTTP, протокол 2025-06-18).

## Tools
| Инструмент | Сервис | readOnly | Права (on-behalf-of) |
|---|---|---|---|
| `absence_create_request` | Отсутствия | нет | только за себя |
| `absence_get_request` | Отсутствия | да | владелец, согласующий, HR BP |
| `absence_decide` | Отсутствия | нет | руководитель команды сотрудника |
| `calendar_team_events` | Календарь | да | участник команды / HR BP |
| `access_catalog` | Доступы | да | все |
| `access_create_request` | Доступы | нет | только за себя, с учётом роли |
| `access_get_request` | Доступы | да | владелец, согласующий, HR BP |
| `access_decide` | Доступы | нет | руководитель команды |

## Requirements

### Requirement: Протокол
Сервер SHALL поддерживать `initialize`, `ping`, `tools/list` (с аннотациями `readOnlyHint`), `tools/call`, уведомления (202).

#### Scenario: [MCP-01] Список инструментов
- **WHEN** клиент вызывает `tools/list`
- **THEN** получает инструменты с аннотациями и вызывает их от имени пользователя

#### Scenario: [MCP-04] Граничные случаи протокола
- **WHEN** GET, неверный токен, битый JSON, неизвестный метод, неверные параметры
- **THEN** 405 / 401 / −32700 / −32601 / −32602

### Requirement: Ошибки и надёжность
Бизнес-ошибки SHALL возвращаться как `isError` и не повторяться; транспортные (5xx, сеть) SHALL повторяться с backoff
(безопасно благодаря ключам идемпотентности); после серии отказов SHALL открываться circuit breaker.

#### Scenario: [MCP-02] Бизнес-ошибка без ретраев
- **WHEN** инструмент отвечает `forbidden`
- **THEN** клиент получает ToolError, повторов нет

#### Scenario: [MCP-03] Ретраи и circuit breaker
- **WHEN** сервис отвечает 503
- **THEN** 3 попытки, затем breaker открыт и запросы не уходят в сервис до сброса

#### Scenario: [MCP-09] Встроенный транспорт
- **WHEN** приложение запущено одним процессом
- **THEN** вызовы идут через тот же MCP-протокол без сети

### Requirement: Делегированная идентичность
Сервисы SHALL проверять права по `X-On-Behalf-Of` независимо от агента (defence in depth).

#### Scenario: [MCP-05] Чужая заявка
- **WHEN** стажёр пытается создать заявку за другого, согласовать свою или прочитать чужую
- **THEN** `forbidden`; руководитель другой команды тоже получает `forbidden`

#### Scenario: [MCP-07] Календарь и чек-лист
- **WHEN** запрашиваются события команды и отмечаются пункты
- **THEN** чужая команда — `forbidden`, отсутствие коллег — только числом, состояние восстанавливается из файла

#### Scenario: [MCP-08] Имитация сбоя и задержки
- **WHEN** включён сбой через admin-API
- **THEN** все вызовы получают 503; admin требует токен; задержка имитируется

#### Scenario: [MCP-06] Отдельный процесс
- **WHEN** запускается `corp-mcp`
- **THEN** он отвечает на `/healthz` и корректно останавливается
