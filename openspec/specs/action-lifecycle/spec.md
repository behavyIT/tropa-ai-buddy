# action-lifecycle Specification

## Purpose
Единый безопасный жизненный цикл побочных эффектов: план → подтверждение → выполнение (MCP) → квитанция.

## Requirements

### Requirement: План без побочных эффектов
Агент SHALL только планировать действия; выполнение — только по явному подтверждению владельца.

#### Scenario: [ACT-01] План не выполняется
- **WHEN** Тропа подготовила заявку на доступы
- **THEN** маршрут не меняется до подтверждения

### Requirement: Ровно один раз
Подтверждение SHALL выполняться атомарным переходом статуса и с ключом идемпотентности в сервисе.

#### Scenario: [ACT-02] Двойной клик
- **WHEN** подтверждение отправлено дважды
- **THEN** внешний ID один и тот же; отмена выполненного — 409

#### Scenario: [ACT-03] Чужое действие
- **WHEN** другой пользователь подтверждает или читает действие
- **THEN** 404

### Requirement: Отказоустойчивость
Сбой сервиса SHALL переводить действие в `failed` с понятным сообщением и возможностью повтора; интерфейс не блокируется.

#### Scenario: [ACT-04] Сбой и повтор
- **WHEN** корпоративный сервис недоступен при подтверждении, затем восстановлен
- **THEN** статус `failed` с сообщением, повтор переводит в `done`

#### Scenario: [ACT-05] Отмена
- **WHEN** стажёр отменяет план
- **THEN** статус `cancelled`, подтверждение после отмены — 409

#### Scenario: [ACT-06] Правка плана отгула
- **WHEN** стажёр меняет даты/комментарий до отправки
- **THEN** план пересчитывается (предупреждения, заголовок); после отправки правка — 409, неверный формат — 400
