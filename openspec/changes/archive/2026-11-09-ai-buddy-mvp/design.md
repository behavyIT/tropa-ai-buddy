# Design: AI-buddy MVP

## Ключевые решения
1. **Детерминированный оркестратор + LLM как языковой слой.** Состояния диалога, права и побочные эффекты — в коде;
   LLM извлекает интент/слоты (structured outputs), формулирует ответ по источникам и оценивает teach-back.
   Альтернатива «свободный агент с tool-calling» отвергнута для HR-действий: сложнее доказать безопасность и воспроизводимость.
2. **Офлайн-режим по умолчанию.** Прототип полностью работает без ключа LLM → экспертиза не зависит от внешнего API.
3. **MCP для корпоративных сервисов.** Инструменты с аннотациями `readOnlyHint`; side-effect-инструменты всегда через подтверждение;
   делегированная идентичность `X-On-Behalf-Of` проверяется сервисом (defence in depth).
4. **ACL до ранжирования.** Недоступные документы не участвуют в поиске и не попадают в промпт.
5. **Exactly-once.** Атомарный переход `planned → executing` в PostgreSQL + ключ идемпотентности в вызове сервиса.
6. **Контент как код.** Маршруты, командные паки, рубрики — YAML/Markdown в репозитории, валидируются при старте и в CI.
7. **Симулированные часы.** Вся логика времени через `clock.Clock` → «машина времени» для демо и детерминированные тесты.

## Риски
- Качество офлайн-NLU ограничено → LLM-режим и сбор пробелов в «Тропинках».
- Ложные срабатывания стоп-тем → консервативный список и маршрутизация к HR BP, а не отказ без выхода.
